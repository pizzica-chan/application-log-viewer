# Application Log Viewer (aplv)

Java アプリケーションのログ（複数ファイル）を **Web UI** で閲覧・検索する障害調査用ツールです。

指定ディレクトリ配下のログファイルを **再帰的に探索** し、複数ファイルを **時系列順に統合** して表示します。

## 機能

- ディレクトリを UI から選択し、配下のログファイルを再帰的に読み込み
- 複数ファイルを時系列ソートして一覧表示
- 各ログ行に **ログファイル名** と行番号を保持
- レベル / ロガー / スレッド / メッセージ / 日時 / 全文 / ログファイルでのフィルタ
- 行クリックで生ログ（スタックトレース含む）とメタ情報を表示
- 含む文字列で一覧の行を 3 色（黄・緑・ピンク）にハイライト（表示のみ。複数に一致した行は番号の小さい欄の色。入力した語はブラウザに保存され、リロードしても残る）
- **セッション追跡**: セッション ID を含むリクエストのログを、同一ファイル・同一スレッドの「はじまり〜おわり」でまとめて表示
- ページング対応
- 検索・追跡条件をツールホーム直下の JSON に保存し、名前を付けて呼び出せる
- 組み込み書式に無いログは、正規表現で書式を自分で定義できる（画面から登録・編集でき、書き方ガイドと試し打ち付き）

大容量ログ向けに **SQLite インデックス** をリポジトリ直下の `tmp/aplv/` に保存します。2 回目以降はファイル変更がなければインデックスを再利用するため、起動が速くなります。7 日以上未使用または件数超過の古い DB は自動削除されます。

全文検索（grep）は **SQLite FTS5（trigram トークナイザ）** で高速化できます（**起動時に `--fts` を指定したときのみ有効**）。検索語が正規表現メタ文字を含まないプレーンな 3 文字以上の文字列のときは、FTS5 でヒット候補を一括で絞り込んでから生ログを照合します（正規表現パターンや 2 文字以下の場合は従来どおり全件スキャンに自動フォールバック）。FTS5 索引は本文の複製を持たない contentless 構成のため、ディスク使用量の増加を抑えつつ、結果は従来の正規表現検索と完全に一致します。

`--fts` を指定しない既定動作では FTS5 索引を作らないため**初回のインデックス構築が高速**です（grep は全件スキャンになります）。検索を多用しインデックス構築時間を許容できる場合に `--fts` を付けてください。

## 前提

- **Docker で動作確認（おすすめ）:** [Docker Desktop](https://www.docker.com/products/docker-desktop/)（ホストに JDK/Maven 不要）
- **ローカル開発:** JDK 8 以上（`javac` を含む JDK。実行のみなら JRE 8 でも可）、Maven 3.6 以上

## ビルド

```powershell
cd D:\workspace\application-log-viewer\aplv-java
mvn -q clean package
```

依存込みの実行可能 JAR `target/aplv-java.jar` が生成されます。

## 起動

```powershell
java -jar aplv-java\target\aplv-java.jar
```

またはリポジトリ直下の `start.bat` を実行します（JAR が無い場合は自動ビルド）。

ブラウザで http://127.0.0.1:8766 を開きます。

起動時にログディレクトリを指定する場合:

```powershell
java -jar aplv-java\target\aplv-java.jar --dir C:\logs\app
java -jar aplv-java\target\aplv-java.jar --dir samples --port 8766
```

| オプション | 説明 | デフォルト |
|-----------|------|-----------|
| `--dir` | 起動時に読み込むログディレクトリ（省略時は UI から選択） | — |
| `--host` | 待ち受けアドレス | `127.0.0.1` |
| `--port` | 待ち受けポート | `8766` |
| `--fts` | 全文検索を FTS5 で高速化（インデックス構築は遅くなる） | 無効 |
| `--format` | ログ書式を固定する（`auto` / `default` / `spring-boot` / `logback` / `iso8601` / `tomcat-juli`、および `aplv-log-formats.txt` に定義した id） | `auto`（自動判定） |

## Docker で動作確認（ローカル）

JDK/Maven をインストールせず、コンテナだけでサンプルログの閲覧まで試せます。

### ワンクリック起動（おすすめ）

|------|----------|

| 停止 | `docker-down.bat` |

PowerShell から起動する場合:

```powershell
.\scripts\one-click-up.ps1
.\scripts\one-click-up.ps1 -FollowLogs   # 起動後にログ追従
```

**Docker Desktop を先に起動**してから、リポジトリ直下で実行します。


### マウントと環境変数

| 項目 | 説明 |
|------|------|
| `./samples` → `/app/logs/samples` | サンプルログ（読み取り専用）。起動時に `--dir` で自動読み込み |
| `./tmp` → `/app/tmp` | SQLite インデックスの永続化 |
| `./aplv-saved-searches.json` → `/app/aplv-saved-searches.json` | 検索条件の永続化（`APLV_HOME` 直下） |
| `./aplv-log-formats.txt` → `/app/aplv-log-formats.txt` | 利用者定義のログ書式（`APLV_HOME` 直下） |
| `APLV_LOG_DIR` | ホスト側のログディレクトリを差し替え（例: `$env:APLV_LOG_DIR="C:\logs\app"`） |
| `APLV_HOME=/app` | コンテナ内のリポジトリルート（インデックス・検索条件の基準） |

検索条件ファイルと書式ファイルがホスト側に無いと Docker がディレクトリを作ることがあるので、`docker-up.bat` は空の JSON を先に作ります。`docker compose` だけ使うときは、同じ 2 ファイルを先に置いてください。

**ホストポート:** 既定は **`8766`** で、`127.0.0.1` にのみ公開します（無認証のため LAN へ露出させない）。競合する場合は `docker-compose.yml` の `ports` を `"127.0.0.1:18766:8766"` のように変更し、ブラウザも合わせてください。

**注意:** ローカル検証専用です。インターネットに公開しないでください。

## Web UI の使い方

1. 画面上部の **ログディレクトリ** にパスを入力するか、**参照...** でディレクトリを選択
2. **読み込み** をクリックすると、配下のログファイルが再帰的に探索・読み込まれます
3. フィルタを設定して **検索**（Enter キーでも可）
4. 行をクリックすると、ログファイル・行番号・生ログ（スタックトレース含む）を表示

### 読み込み対象のログファイル

以下のファイル名パターンに一致するファイルを再帰的に探索します。

- `application*.log*`, `server*.log*`, `spring*.log*`
- `catalina*.log*`, `localhost*.log*`, `app*.log*`
- `*.log`, `*.out`

`.git` や `node_modules` などのディレクトリはスキップします。圧縮ファイル（`.gz` 等）は未対応です。

### フィルタ

| 項目 | 説明 | 例 |
|------|------|-----|
| レベル | ログレベル | `ERROR` / `WARN,ERROR` |
| ロガー | ロガー名（正規表現） | `HogeController` |
| スレッド | スレッド名（正規表現） | `main` |
| メッセージ | 1行目メッセージ（正規表現） | `NullPointer` |
| 開始 / 終了 | 日時範囲 | 日時ピッカー |
| 全文検索 | エントリ全体（スタックトレース含む）への正規表現 | `Exception` |
| ログファイル | 絶対パスへの正規表現 | `application.log` |

### 検索条件の保存

「保存した検索条件」から、いま選んでいるタブ（検索 / リクエスト追跡）の条件に名前を付けて保存できます。保存先は **ツールホーム直下** の `aplv-saved-searches.json` です（`APLV_HOME`。未設定時はリポジトリ直下）。実際に読み書きしているパスは、ダイアログの「保存先」に表示されます。

条件に含まれる正規表現は **文字列として** 保存・読み込みします。ファイルを読んだ時点ではマッチもコンパイルも行いません（検索や追跡を実行したときだけ正規表現になります）。

手で JSON を編集する場合、正規表現の `\` は JSON の規則で `\\` と書いてください（例: `\d+` → `"\\d+"`）。項目が 1 件だけ壊れていても、読める件はそのまま使えます（壊れた件は次に保存したときにファイルから消えます）。ファイル全体の JSON が壊れているときは読み込めません。

保存できる条件は 200 件までです。手編集で 200 件を超えたファイルは、読み込みは 200 件までで打ち切り、そのままでは保存・削除ができません（書き戻すと読み込めていない条件が消えるため）。ファイルを直接編集して減らしてください。

### セッション追跡

同じ Web アプリケーションのセッションを追うための機能です。条件欄の上にある **リクエスト追跡** タブに切り替えて使います（通常の検索は **検索** タブ）。結果の表・ハイライト・ページャは両方のタブで共通です。

判定方法は 2 つから選べます。

| 判定方法 | 内容 | 向き不向き |
|---|---|---|
| はじまり／おわりの語で区切る（既定） | 指定した語の行から語の行までを 1 リクエストとする | 語が分かっているなら**こちらが正確** |
| ID の前後 n 秒 | セッション ID の行の前後 n 秒にある、同じファイル・同じスレッドの行を 1 リクエストとみなす | 語を決めなくても使える**お手軽版。誤検知あり** |

「ID の前後 n 秒」は、語を調べなくてもすぐ使える代わりに、時間だけで区切るので**スレッドの使い回しによって、直前・直後に同じスレッドが処理した別のリクエストの行まで取り込むことがあります**（秒数が短ければ、逆に同じリクエストの行を取りこぼします）。ID が近い時間に続けて出たときは 1 つのリクエストにまとめます。

| 項目 | 説明 | 例 |
|------|------|-----|
| 判定方法 | 上の 2 つから選ぶ | はじまり／おわりの語で区切る |
| セッション ID など | 追いたい識別子。スタックトレースを含むエントリ全体から、**正規表現ではなく文字列として**探す（大文字小文字を区別） | `8F3A2C91D4E6B7A0.node1` |
| リクエストのはじまり | はじまりの行の 1 行目メッセージに一致する正規表現 | `^リクエスト開始` |
| リクエストのおわり | おわりの行の 1 行目メッセージに一致する正規表現 | `^リクエスト終了` |
| 最大所要時間（分） | 1 リクエストとみなす時間の上限。セッション ID のある行から前後どちらも、この時間を超えたら打ち切る（既定 10 分。語で区切るときのみ） | `10` |
| 前後の秒数 | ID の行の前後この秒数を同じリクエストとみなす（既定 10 秒。前後 n 秒のときのみ） | `10` |
| この語を含むリクエストだけ | 一致する行を含むリクエストだけを表示する正規表現 | `PaymentException` |
| この語を含むリクエストを除く | 一致する行を含むリクエストを除く正規表現 | `/health` |

セッション ID を含む行を起点に、**同じログファイル・同じスレッド**で「はじまり」から「おわり」までを 1 リクエストとして、リクエストごとに見出しを付けて表示します。スレッドはプールで使い回されるため、スレッドだけでなく、はじまり・おわりで区切ります。はじまり・おわり・最大所要時間・絞り込みの 2 欄はブラウザに保存されます（セッション ID は保存しません）。

絞り込みは**リクエストの塊単位**です。どれか 1 行でも一致すれば、そのリクエスト全体を残す（除く）ことになります。判定はスタックトレースを含むエントリ全体に対して行うため、例外クラス名のようにスタックトレースの中にしか無い語でも絞れます。両方を指定した場合は「含む」を満たし、かつ「除く」に当たらないリクエストだけが残ります。

**制限事項**（画面の「判定方法と制限事項」にも表示しています）

- 同期処理（1 リクエストを 1 スレッドが最後まで処理する。Tomcat + Spring MVC など）が前提です
- 非同期処理（`@Async`、`CompletableFuture`、`DeferredResult`、Servlet の非同期処理など）で別スレッドに出たログは含まれません
- WebFlux / Netty など、1 スレッドで複数のリクエストを交互に処理する方式では正しく判定できません
- 同じログファイルの中だけを見ます。リクエストの途中でのローテートや、レベル・ロガー別にファイルを分けている場合は取りこぼします
- （語で区切るとき）おわりが出ないまま終わったリクエストは、同じスレッドの次のはじまりの直前、または最大所要時間で打ち切ります
- 表示は最大 200 リクエスト、1 リクエストあたり最大 1,000 行です。絞り込みで落としたリクエストも 1 件として数えるため、除外が多いときは調べる件数の上限（2,000 リクエスト）で打ち切ることがあります
- 絞り込みの判定に使うのは表示対象の行だけです。1,000 行を超えたリクエストでは、切り落とした後ろにしか無い語では絞り込めません
- 1,000 行で切ったリクエストでは、切り落とした後ろにあるセッション ID の行も同じリクエストとして扱います（「ID を含む行」の件数には入りますが、行としては表示しません）
- 追跡結果の「マッチ行をハイライト」は、スタックトレースの中にしか無い語には色が付きません（1 行目までの列だけで判定します。通常の一覧ではスタックトレースも対象です）
- 「検索」タブの条件（レベル・期間など）は追跡には効きません。リクエスト内の行はレベルに関係なくすべて表示します（検索タブで「検索」を押すか、「検索結果に戻る」で通常の一覧に戻ります）
- （前後 n 秒のとき）時間だけで区切るため、同じスレッドが直前・直後に処理した別のリクエストの行が混ざることがあります。ID が近い時間に続けて出たときは 1 つのリクエストにまとめます
- （前後 n 秒のとき）どのリクエストにも属さない行（セッション破棄のログなど）も、前後 n 秒に同じスレッドの行があればまとめて表示します
- ログファイルを読み出せない場合（検索中に削除された等）はエラーになります。黙って結果が欠けることはありません
- `--fts` なしでは起点探しが全件走査になります（一覧の全文検索と同じ）。実測値は `SessionTrace` のコメントを参照

**サンプル 1（最小構成）**: `samples/session/` に、判定のパターンを一通り含む小さなログがあります。`--dir samples` で起動し、上の表の例をそのまま入力すると、次の 7 リクエストが表示されます。

| # | スレッド | 見どころ |
|---|----------|----------|
| 1 | exec-4 | ローテート前のファイル（`webapp.2026-06-16.0.log`）。おわりは次のファイルにあるため「おわり未検出」 |
| 2 | exec-4 | ローテート後のファイル（`webapp.log`）。はじまりが前のファイルにあるため「はじまり不明」 |
| 3 | exec-1 | 通常のリクエスト。ID を含まない行（在庫確認）も同じリクエストとして表示され、同時刻の exec-2 の別セッションは混ざらない |
| 4 | exec-2 | ID がスタックトレースにしか無い。非同期スレッド `task-1` のメール送信ログは含まれない（制限事項） |
| 5 | exec-3 | 例外でおわりが出ないまま抜けた。同じスレッドの次のはじまり（別セッション）の直前で打ち切り |
| 6 | Catalina-utility-1 | セッション破棄のログ。どのリクエストにも属さない「単独の行」 |
| 7 | exec-5 | ファイル末尾までおわりが無い |

**サンプル 2（冗長構成・ログ量多め）**: `samples/session-cluster/` に、アプリサーバ 3 台（`app1.log` / `app2.log` / `app3.log`、合計約 1,100 行）を想定したログがあります。10 セッションが同じ時間帯に混在し、1 つのセッションのリクエストが**振り分けでインスタンスを行き来**します。セッション ID に `D41B8E2F5A7C4903` を入れて追跡すると、次のことが確認できます。

- 3 つのログファイルにまたがった 15 リクエスト（通常 12 + 並列 2 + セッション破棄の単独行 1）が、時刻順に 1 つの画面に並ぶ
- 同じ名前のスレッド（`http-nio-8080-exec-1` など）が別インスタンスにもあるが、ファイルが違えば混ざらない。09:30:04 には、同じセッションの**並列リクエスト 2 本が別インスタンスの同じ名前のスレッド**に同時刻で乗っている
- 他の 9 セッションやロードバランサのヘルスチェック（`/health`）は入ってこない
- 「この語を含むリクエストだけ」に `PaymentException` を入れると、決済に失敗した 1 リクエストだけが残る（スタックトレースの中にしか無い語で絞れる）

このログは `python scripts/gen-session-cluster.py` で生成しています（乱数の種を固定しているので、実行するたびに同じログができます）。

## 対応ログ形式

### Tomcat アプリログ（主形式）

```
2026-06-15 00:19:11.705[ajp-nio-8009-exec-24][TRACE][org.hogehoge.jdbc.HogeUtil] - ログ本文
```

形式: `YYYY-MM-DD HH:MM:SS.mmm[Thread][LEVEL][Logger] - Message`

### その他の Java ログ

```
2026-05-27 00:00:03.965[HogeController][ERROR][main] - ログ本文
```

形式: `YYYY-MM-DD HH:MM:SS.mmm[Logger][LEVEL][Thread] - Message`

Thread に `[]` を含む場合（例: `main:[12345] ch[00]`）も対応します。

いずれも LEVEL は 2 番目の `[]` 内にあり、FQCN（`.` 含む）やスレッド名パターンから自動判別します。

### 切り替えできる書式

上記 2 つは既定書式（`default`）として扱います。ほかに以下へ切り替えられます。

| 書式 | 例 |
|------|-----|
| `spring-boot` | `2026-06-15 00:19:11.705  INFO 12345 --- [main] c.e.Hoge : Message` |
| `logback` | `2026-06-15 00:19:11,705 INFO  [main] com.example.Hoge - Message` |
| `iso8601` | `2026-06-15T00:19:11.705 INFO [main] com.example.Hoge - Message` |
| `tomcat-juli` | `15-Jun-2026 00:19:11.705 INFO [main] org.apache.catalina.startup.Catalina.start Message` |

- `logback` はレベルとスレッドの並びが逆（logback 既定 / log4j 一般形）のどちらでも読めます。
  ミリ秒の区切りは `.` でも `,` でも構いません
- `iso8601` は log4j2 の `%d{ISO8601}`（`,` 区切り）と、タイムゾーンオフセット付き
  （`+09:00` / `Z`）にも対応します。Spring Boot 3.4 以降の既定（ISO 日時 + オフセット）は
  `spring-boot` で読めます
- 同時に読み込むファイルはすべて同じ書式である前提です

**書式の決め方**: 既定は自動判定で、先頭ファイルの冒頭 500 行をサンプリングして
最もよく一致する書式を選びます。判定結果は画面の概要行に出ます。外れた場合は
ログディレクトリ欄のセレクトで明示指定できます（CLI は `--format <id>`）。
書式を変えるとインデックスは作り直されます。

**組み込み書式で読めない形式**: logback の既定（`%d{HH:mm:ss.SSS}` で日付が無いもの。
日付が無いと日をまたいで並べられないため）、java.util.logging の SimpleFormatter
（1 エントリが 2 行）、log4j 1.x の TTCC（`%r` が起動からの相対ミリ秒）、JSON Lines。
1 行で完結し、日付と時刻が書かれている形式なら、次の **書式を自分で定義する** で読めます。

### エントリと継続行

書式が何であれ（組み込みでも、次の **書式を自分で定義する** でも）、行の扱いは同じです。

```
2026-06-15 00:19:11.705[main][ERROR][com.example.HogeController] - 処理に失敗しました
java.lang.NullPointerException: null
	at com.example.HogeController.process(HogeController.java:42)
```

- **選んだ書式に一致した行**を、1 エントリの先頭行として扱います
- **一致しなかった行**は直前のエントリの続き（スタックトレース等）として同じエントリに含め、
  詳細表示・全文検索の対象にします
- 直前にエントリが無いまま一致しなかった行（ファイル先頭の孤立行など）は読み飛ばします。
  エラーにはせず、件数と例を画面に出します

### 書式を自分で定義する

組み込み書式に無いログは、正規表現で書式を自分で定義すると読めるようになります。
**中身の管理は利用者の責任**です。

**画面から登録できます。** ログディレクトリ欄の **書式の管理...** を開くと、一覧・登録・
編集・削除ができます。ダイアログには次の 2 つがあり、正規表現を 1 から書かずに済みます。

- **書き方ガイド**: 日時・レベル・スレッドなどの**よく使う部品**が並んでいて、クリックすると
  正規表現の欄に差し込まれます。ログの行を貼り付けて、行ごとに変わるところだけを部品で
  置き換えていく、という進め方ができます。日時の部品を選ぶと**日時書式の欄も一緒に入ります**
  （日時書式だけを選ぶボタンもあります）
- **この行で試す**: 読みたいログを 1 行そのまま貼ると、各項目に何が取れるかを返します。
  当たらないときは、正規表現が合っていないのか日時の読み方が合っていないのかを区別して
  示します（登録はされません）

保存先は **ツールホーム直下の `aplv-log-formats.txt`** です（`APLV_HOME`。未設定時は
リポジトリ直下）。実際のパスはダイアログの「保存先」に出ます。**このファイルを直接編集
してもかまいません**。画面から入れても手で書いても、同じ検査を通ります
（[docs/aplv-log-formats.example.txt](docs/aplv-log-formats.example.txt) が雛形です）。

```
[my-app]
name = 自社アプリ形式
pattern = ^(?<ts>\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2}\.\d{3}) (?<level>\w+) \((?<thread>[^)]*)\) (?<logger>\S+) : (?<message>.*)$
timestamp = yyyy/MM/dd HH:mm:ss.SSS
```

上の定義は、次のような行を読めるようにします。

```
2026/06/15 00:19:11.705 INFO (main) com.example.Hoge : 処理を開始します
```

| 項目 | 内容 |
|------|------|
| `id` | 英小文字・数字・ハイフン。`--format` と画面の選択に使う。組み込み書式と同じ id は使えない |
| `name` | 画面のプルダウンに出す名前。省略すると `id` |
| `pattern` | 1 行に当てる Java の正規表現。名前付きグループで項目を取り出す |
| `timestamp` | `ts` の読み方（Java の `DateTimeFormatter`）。月名（`MMM`）は英語前提 |

**名前付きグループ**: 取り出す項目は `(?<ts>...)` のように名前を付けて指定します。
名前は 5 つ決まっていて、**`ts`（日時）だけが必須**です。`level` / `thread` / `logger` /
`message` は必要なものだけ付ければよく、付けなかった列は空欄になります。レベルは
組み込み書式と違って語の検査をしないため、`NOTICE` でも `警告` でも通ります
（絞り込みの比較を揃えるため、`info` は `INFO` のように大文字へ直します）。

**ファイルの書き方**: `[id]` で 1 つの書式が始まり、`キー = 値` を並べます。区切りは最初の
`=` だけなので、値に `=` が入っていてもかまいません。値の前後の空白は取り除くので、
正規表現の末尾で空白に当てたいときは、空白 1 文字を表す `[ ]` を書いてください
（この形式の決まりではなく、正規表現としてそう解釈されます）。コメントは**行頭の `#` だけ**で、
値の途中の `#` はただの文字です。

**うまくいかないとき**: 多いのは次の 3 つです。

- **行の全部を書いていない。** `^` から `$` まで、行の最初から最後までが当たる形にします
- **空白の数が違う。** レベルの桁を揃えるログでは、`INFO  ` のように後ろが空いたり
  （左詰め。logback の `%-5level` など）、`  INFO` のように前が空いたり
  （右詰め。Spring Boot の `%5p` など）します。空白 1 個ではなく空白 1 個以上（` +`）を
  使ってください
- **角括弧が入れ子になっている。** `[^\]]*` は最初の `]` で止まるため、
  `[pool-1[worker-3]]` のようなスレッド名には一致しません。ガイドの入れ子用の部品
  （`(?:[^\[\]]|\[[^\]]*\])*`）を使ってください

**読めない形式**:

- 1 エントリが 2 行以上になる形式。先頭行に一致しなかった行は、直前のエントリの続き
  （スタックトレース）として扱われます
- `(?x)`（空白を無視し `#` 以降をコメントにする書き方）。コメントの中に書いたグループを、
  アプリ側が「ある」と数えてしまいます。使った場合は取り込み時にどの書式が原因かを示して
  失敗します（黙って誤読はしません）

**そのほか**:

- 書式は自動判定の候補にも入ります。組み込み書式と同点なら組み込みが選ばれます
- 定義を直すと索引は作り直されます（`id` が同じでも中身が変われば作り直します）
- 書き間違いはその 1 件だけに留まります。残りの書式はそのまま使え、読み飛ばした理由は
  行番号つきで標準エラーに出ます
- ただし**読み飛ばしがある間は、画面からの登録・削除ができません**。書き戻せるのは
  読めた書式だけなので、そのまま保存すると壊れた部分が消えてしまうためです。直すか、
  その部分を消してください
- 手で書いたコメントは、画面から登録・削除しても残ります（ファイルの先頭の塊と、
  各 `[id]` の直前に書いた分）。節の中（キーの行のあいだ）に書いたコメントは残りません
- 実在しない日時（`2026/02/31`、`24:00:00` など）の行は取り込みません。Java の既定では
  月末や翌日へ黙って寄せられ、書かれていない時刻で並んでしまうためです

**性能**: 正規表現で読むぶん、組み込み書式より解析は重くなります。100 万行の取り込みで
2,975ms → 3,134ms（+5.3%、7 回の中央値。同じ内容を書式違いで書いた別ファイル同士の比較）でした。**この重さを払うのは、この書式を選んだ
取り込みだけ**で、組み込み書式の速度は変わりません。詳細は
[docs/performance-report.md](docs/performance-report.md) の 11 章。

**暴走する正規表現について**: 入れ子の量指定子（`(a+)+` のような書き方）は後戻りが
爆発し、1 行の照合が事実上終わらなくなることがあります。アプリは行の長さに見合わない
照合を打ち切り、**どの書式のどの行で止めたかを示して取り込みを失敗させます**。
固まったまま返ってこない状態にはなりませんが、書式は直す必要があります。

## パフォーマンス設計

| 項目 | 内容 |
|------|------|
| メモリ | エントリ本文（スタックトレース）は DB に載せず、元ファイルの **byte offset** から都度読み出し |
| インデックス | 解析結果を `{リポジトリ}/tmp/aplv/`（SQLite）に **永続化** |
| 解析 | 組み込み書式はバイト列でヘッダ行を高速判定し、一致行のみ UTF-8 デコード（利用者定義の書式は全行を UTF-8 デコードして正規表現で照合するぶん重い） |
| 並列化 | 複数ログファイルを **並列パース**、SQLite 書き込みは単一ライタースレッド |
| Web サーバ | JDK 内蔵 `com.sun.net.httpserver` による自前実装（Tomcat 等不要） |

詳細は [aplv-java/README.md](aplv-java/README.md) を参照してください。

インデックス構築・検索の最適化については、実測値と判断の根拠を[docs/performance-report.md](docs/performance-report.md) にまとめています（MyBatis-log-viewer へ横展開した際、同じ手法が逆効果になった件を含む）。
