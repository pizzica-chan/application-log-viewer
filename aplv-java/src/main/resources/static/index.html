    セッション ID を含むリクエストのログを、リクエストごとにまとめて表示します。

    どこまでを 1 リクエストとみなすかの決め方です。 はじまり／おわりの語で区切るは、指定した語の行から語の行までをひとまとまりにします。 ID の前後 n 秒は、語を決めずにセッション ID の行の前後 n 秒でまとめます （手軽な代わりに、同じスレッドが前後に処理した別のリクエストを巻き込むことがあります）。
    セッション ID が出た行の前後この秒数にある、同じログファイル・同じスレッドの行を 1 リクエストとみなします。短くすると同じリクエストの行を取りこぼし、 長くすると別のリクエストの行まで拾います（既定 10 秒）。
    1 リクエストとみなす時間の上限です。セッション ID のある行から、はじまりを遡るときも おわりを探すときも、この時間を超えたら打ち切ります（既定 10 分）。

    お手軽ですが、誤検知があります。 はじまり・おわりの語を決めなくても使えますが、時間だけで区切るため、 スレッドの使い回しで直前・直後に同じスレッドが処理した別のリクエストの行まで 取り込むことがあります（秒数が短ければ、逆に同じリクエストの行を取りこぼします）。 はじまり・おわりの語が分かっているなら、そちらのほうが正確です。

    判定方法と制限事項

    セッション ID を含む行を起点に、同じログファイル・同じスレッドの行を 1 リクエストとしてまとめます。どこで区切るかは「判定方法」で選びます。

    • はじまり／おわりの語で区切る: 指定した語の行から語の行まで。判定はメッセージ（1 行目）への正規表現です（大文字小文字は区別しません）。
    • ID の前後 n 秒: セッション ID の行の前後 n 秒にある行。語は使いません。ID が続けて出るあいだは 1 つにまとめます。

    セッション ID はどちらの判定方法でも、スタックトレースを含むエントリ全体から、 正規表現ではなく文字列として探します。

    • 同期処理が前提です。1 リクエストを 1 スレッドが最後まで処理するアプリ（Tomcat + Spring MVC など）で正しく判定できます。
    • 非同期処理で別スレッドに出たログは含まれません。（@Async、CompletableFuture、DeferredResult、Servlet の非同期処理など）
    • WebFlux / Netty など、1 スレッドで複数のリクエストを交互に処理する方式では正しく判定できません。範囲に他のリクエストのログが混ざります。
    • 同じログファイルの中だけを見ます。リクエストの途中でローテートした場合や、レベル・ロガーごとにファイルを分けている場合は、他のファイルに出たログを取りこぼします。
    • 語で区切るとき: おわりが出ないまま終わったリクエストは、同じスレッドの次のはじまりの直前、または最大所要時間で打ち切ります（「おわり未検出」と表示）。
    • 語で区切るとき: はじまりが見つからなくても、次のはじまりより先におわりがあれば 1 リクエストとして扱います（「はじまり不明」と表示）。
    • 語で区切るとき: どのリクエストの範囲にも入らない行（セッション破棄のログなど）は、その行だけを「単独の行」として表示します。
    • スレッド名を出力しない行は、同じスレッドの行を判断できないため単独の行になります。Spring Boot 既定の書式はスレッド名を 15 文字に切り詰めるため、まれに別スレッドと区別できないことがあります。
    • 表示するのは最大 200 リクエスト、1 リクエストあたり最大 1,000 行です。
    • 「この語を含む／含まないリクエスト」の絞り込みは、行ではなくリクエストの塊単位です。どれか 1 行でも一致すれば、そのリクエスト全体を残す（除く）ことになります。判定はスタックトレースを含むエントリ全体に対して行います。
    • 絞り込みで落とすリクエストも 1 件として数えるため、除外が多いときは調べる件数の上限（2,000 リクエスト）で打ち切ることがあります。
    • 絞り込みの判定に使うのは、1 リクエストあたり最大 1,000 行の表示対象だけです。1,000 行を超えたリクエストでは、切り落とした後ろにしかない語では絞り込めません。
    • 1,000 行で切ったリクエストでは、切り落とした後ろにあるセッション ID の行も同じリクエストとして扱います。「ID を含む行」の件数には入りますが、行としては表示しません。
    • 追跡結果の「マッチ行をハイライト」は、時刻・レベル・ロガー・スレッド・メッセージ（1 行目）・ログファイルだけで判定します。スタックトレースの中にしかない語は色が付きません（通常の一覧ではスタックトレースも対象です）。
    • 前後 n 秒のとき: 時間だけで区切るため、同じスレッドが直前・直後に処理した別のリクエストの行が混ざることがあります（誤検知）。ID が近い時間に続けて出たときは、1 つのリクエストにまとめます。
    • 前後 n 秒のとき: どのリクエストにも属さない行（セッション破棄のログなど）も、前後 n 秒に同じスレッドの行があればまとめて表示します。
    • 「検索」タブの条件（レベル・期間など）は追跡には効きません。リクエスト内の行はレベルに関係なくすべて表示します。検索タブで「検索」を押すか、「検索結果に戻る」で通常の一覧に戻ります。

        書き方ガイド
        
          
          
          
          
          考え方
          
          
          
            まず、読みたいログの 1 行を正規表現の欄にそのまま書き写します。
            次に、行によって変わる部分（日時やレベルなど）だけを、下の「部品」ボタンが
            挿入する正規表現に置き換えます（その部分の文字列を消し、パターンを書くイメージです）。
            部品には ts などの名前が付いており、行に一致したときに取り出した値が一覧の列になります。
          
          
          
          
            
          
              ログの行
              2026/06/15 00:19:11.705 INFO (main) com.example.Hoge : 開始しました
            
          
            
          
              書き写す
              ^2026/06/15 00:19:11.705 INFO (main) com.example.Hoge : 開始しました$
            
          
            
          
              置き換え例
              ^(?<ts>\d{4}/\d{2}/\d{2} \d{2}:\d{2}:\d{2}\.\d{3}) (?<level>\w+) \((?<thread>[^)]*)\) (?<logger>\S+) : (?<message>.*)$
            
          
          
          
          
          

          
          
          
          取り出す項目（5 つ）
          
          
          
            必須は ts（日時）だけです。
            level・thread・logger・message は
            必要なものだけ付ければよく、付けなかった列は空欄になります。
          
          
          
          

          
          
          
          部品（正規表現のひな形）
          
          
          
            クリックすると正規表現の欄に差し込みます（カーソルの位置に入ります）。
          
          

          
          日時（どれか 1 つを選ぶ）
          
          
          
            
            
            
            
            
            
          
          

          
          レベル・スレッド・ロガー・メッセージ
          
          
          
            
            
            
            
            
            
            
            
          
          

          
          つなぎ・そのほか
          
          
          
            
            
            
            
            
            
          
          

          
          
            行によって出たり出なかったりする部分があるときは、そこを
            (?: と )? ではさみます。たとえば
            --- が付く行と付かない行が混ざるなら (?:--- )? です。
          
          
          
          
            スレッド名が [pool-1[worker-3]] のように、角括弧の中にもう 1 組入っているときは、
            「スレッド [main]」ではなく「スレッド [pool-1[worker-3]]」のボタンを選んでください。
            前者は最初の ] で切れてしまい、行に一致しなくなります。
            後者は [main] のような普通の行にもそのまま使えます。
            ロガーが同じ形のときは、このボタンを押してから thread を logger に書き換えてください。
          
          
          
          
            ログの中の . [ ] (
            ) + * ? |
            $ ^ \ は、そのままだと別の意味になります。
            文字として書きたいときは前に \ を足してください
            （. なら \.）。
          
          
          
          

          
          
          
          日時書式（日時欄）
          
          
          
            ts で取り出した文字列を、どう読むかの指定です。
            正規表現ではなく Java の日時パターン（DateTimeFormatter）を書きます。
            上の日時の部品を選ぶと、この欄も一緒に入ります。
            下のボタンに無い記号が要るときは、
            Java の記号表を参照してください
            （オフラインでは開けません）。
            正規表現を先に組み立てたいときは、空のままで構いません（その間は
            この行で試す が、取り出せた文字列をそのまま見せます）。
          
          
          
          クリックすると日時書式の欄に入ります
          
          
          
            
            
            
            
            
            
            
            
          
          
          
          
            ts が取り出した文字列と、この日時パターンの形はぴったり合わせてください。
            区切りが違うだけでも読めません。日付を含まない書式（時刻だけ）は、
            日をまたいだときに並べられないため使えません。
            時刻はログに書かれたままの値として扱い、タイムゾーンの変換はしません。
          
          
          
          

          
          
          
          うまくいかないとき
          
          
          
            読みたいログを 1 行そのまま「試すログの行」に貼り、
            この行で試す を押してください。
            各項目に何が取れたか、一致しないときはどこを直せばよいかが出ます
            （登録はされません）。よくある原因は次の 3 つです。
          
          
          
            
            
          • 
              行の全部を書いていない
              ^ から $ まで、行の最初から最後までが一致する形にします。
              途中で終わっていると一致しません。
            
            • 
            
          • 
              空白の数が違う
              レベルの桁を揃えるログでは、INFO   のように後ろが空いたり
              （左詰め。logback の %-5level など）、  INFO
              のように前が空いたり（右詰め。Spring Boot の %5p など）します。
              空白 1 個ではなく空白 1 個以上（ +）を使ってください。
            
            • 
            
          • 
              角括弧が入れ子になっている
              [^\]]* は最初の ] で止まるため、
              [pool-1[worker-3]] のようなスレッド名には一致しません。
              上の「スレッド [pool-1[worker-3]]」のボタンを使ってください。
            
            • 
          
          
          
          
            外れ方は 2 通りあり、画面への出方が違います。
          
          
          
            
            
          • 
              正規表現は一致したが、日時を読めない
              読み飛ばしとして件数と例が出ます。直すのは正規表現ではなく
              日時書式のほうです。
            
            • 
            
          • 
              正規表現がそもそも一致しない
              継続行（スタックトレース）と見分けられないため、
              直前のエントリの本文として扱います。読み飛ばしには数えません。
            
            • 
          
          
          
          

          
          
          
          読めない形式
          
          
            
            
          • 
              1 エントリが 2 行以上になる形式
              2 行目以降は直前のエントリの続き（スタックトレース）として扱うので、
              そこに書かれたレベルやロガーは列に出ません。
              1 行目だけで項目がそろう形式にしてください。
            
            • 
            
          • 
              (a+)+ のように繰り返しを入れ子にした書き方
              照合が急激に重くなるため、行の長さに見合わない照合は打ち切り、取り込みを
              失敗させます（画面が固まったままにはなりません）。
            
            • 
            
          • 
              (?x)（空白を無視する書き方）
              コメントの中に書いたグループを、アプリ側が「ある」と数えてしまいます。
            
            • 
          
          
          
          

          
          
          
          登録したあと
          
          
          
            書式のプルダウンから選んで 読み込み を押すと、その書式で取り込みます
            （自動判定に任せることもできます）。書式を直すとインデックスは作り直されます。
            id を変えなくても、正規表現や日時書式を変えれば作り直しの対象です。
